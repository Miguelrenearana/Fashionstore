# CU-01 — Gestión de usuarios y autenticación

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-01 | Autenticar usuarios con JWT y gestionar cuentas (alta, listado, edición) con control por roles | Administrador, Usuario/Empleado | Usuario/Empleado |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| El usuario tiene una cuenta activa y contraseña válida. Admin autenticado para gestionar cuentas. | 1. El usuario envía POST /auth/login (email + contraseña). 2. El sistema valida credenciales y emite un token JWT con roles. 3. GET /auth/me devuelve perfil y roles. 4. El administrador lista usuarios (GET /users), crea (POST /users) y edita (PATCH /users/{id}). | El usuario queda con sesión activa (JWT). Cuentas creadas/actualizadas en BD con rol asignado. | Credenciales inválidas → 401. Cuenta inactiva → 401. Email duplicado → 409. Rol inexistente → 422. Sin rol admin → 403. Sin token → 401. |
