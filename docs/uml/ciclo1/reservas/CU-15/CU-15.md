# CU-15 — Gestionar reserva de múltiples prendas

> Paquete: **Reservas y experiencia de compra**

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-15 | Permitir al cliente seleccionar varias prendas y reservarlas para posteriormente acudir a una sucursal y probarlas físicamente, registrando las variantes seleccionadas, la sucursal y el horario aproximado de atención | Cliente | Cliente |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| Cliente autenticado. Existe stock (disponible + reservado) en la sucursal para las variantes solicitadas. | 1. El cliente agrega varias prendas al carrito (`POST /cart/items`). 2. Confirma la reserva indicando la sucursal (`POST /cart/checkout`). 3. El sistema reserva el stock (`reserved_quantity`) y genera `pickup_code` y `expires_at`; el horario aproximado puede indicarse en las notas. 4. El carrito se vacía y se muestra la reserva. 5. El cliente consulta (`GET /reservations/me`) o cancela la reserva (liberando stock). | Se crea una reserva PENDING asociada a la sucursal con sus variantes, y el stock queda apartado temporalmente. | Sin token → 401. Stock insuficiente → 422. Carrito vacío o sin variantes → 422. Cancelación de una reserva ajena → 403. Vencimiento (30 min) → EXPIRED y se libera stock. |
