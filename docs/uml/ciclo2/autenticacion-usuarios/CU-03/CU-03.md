# CU-03 — Recuperación de contraseña

> Paquete: **Autenticación y gestión de usuarios**

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-03 | Permitir al cliente recuperar el acceso a su cuenta cuando olvida su contraseña: solicita un token de restablecimiento por correo y lo usa para definir una nueva contraseña | Cliente | Cliente |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| El cliente tiene una cuenta registrada en el sistema. | 1. El cliente solicita la recuperación con su correo (`POST /auth/forgot-password`). 2. El sistema genera un token de un solo uso con vencimiento de 30 minutos, guarda su hash en `password_reset` y lo entrega por correo (mock: notificación interna). 3. El cliente envía token y nueva contraseña (`POST /auth/reset-password`). 4. El sistema valida el token (hash, vigencia, no usado) y actualiza `password_hash`. 5. El cliente inicia sesión con la contraseña nueva. | La contraseña fue restablecida y el token quedó invalidado; el cliente vuelve a autenticarse. | Correo inexistente → respuesta genérica (no revela datos). Token inválido, vencido o ya usado → 401/422. Contraseña con menos de 8 caracteres → 422. |
