# CU-05 — Registro y gestión de perfil de cliente

> Paquete: **Autenticación y gestión de usuarios**

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-05 | Permitir al cliente registrarse en la tienda y gestionar su perfil (datos personales, preferencias y talla de vestir) | Cliente | Cliente |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| El cliente no tiene cuenta activa con ese correo | 1. El cliente se registra (`POST /auth/register`): se crean `User` con rol CLIENT y su fila `Client`, y la sesión se inicia automáticamente con el JWT (el frontend usa `storeToken`). 2. El cliente consulta su perfil (`GET /clients/me`). 3. El cliente actualiza sus datos y preferencias (`PATCH /clients/me`). | El cliente quedó registrado con sesión iniciada y sus datos de perfil quedaron actualizados. | Correo ya registrado → 409. Datos inválidos (nombres cortos, correo mal formado, contraseña < 8) → 422. Acceso sin token o con rol distinto de CLIENT → 401/403. |
