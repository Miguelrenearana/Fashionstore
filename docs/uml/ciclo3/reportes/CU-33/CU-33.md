## Endpoints

| Método | Ruta | Descripción |
| --- | --- | --- |
| GET | `/api/v1/reports/indicators?start_date=...&end_date=...&branch_id=1` | KPIs de ventas (GET con query params) |
| POST | `/api/v1/reports/indicators` | KPIs de ventas (cuerpo JSON) |
| GET | `/api/v1/reports/stock?branch_id=1&threshold=10` | Stock bajo y agotado |
| GET | `/api/v1/reports/sales-by-period?period_type=daily|weekly|monthly&start_date=...&end_date=...&branch_id=1` | Ventas agrupadas por período |
| GET | `/api/v1/reports/top-products?start_date=...&end_date=...&limit=10&branch_id=1` | Top N productos más vendidos |
| GET | `/api/v1/reports/low-stock?branch_id=1&threshold=10` | Alias de /stock |
| GET | `/api/v1/reports/inventory-turnover?start_date=...&end_date=...&branch_id=1` | Rotación de inventario |

## Validaciones

- Solo rol ADMIN (middleware `_require_admin`)
- `start_date` < `end_date` obligatorio
- `period_type` ∈ {daily, weekly, monthly}
- `threshold` ≥ 0 (default 10)
- `limit` 1-100 (default 10)
- `branch_id` opcional (todas si no se especifica)

## Modelo de Datos (Response Schemas)

- **IndicatorsResponse**: total_sales, total_revenue, avg_ticket, orders_count, top_branch_id
- **LowStockResponse**: low_stock[], out_of_stock[], summary {total_low, total_out}
- **SalesByPeriodResponse**: periods[{period, sales_count, revenue}], total
- **TopProductsResponse**: products[{variant_id, garment_name, size, color, qty_sold, revenue}], total
- **InventoryTurnoverResponse**: turnover_rate, days_inventory, cogs, avg_stock

## Notas

- Consultas optimizadas con agregaciones SQL (SUM, COUNT, AVG, DATE_TRUNC)
- Índices en Sale(created_at, branch_id, status), Inventory(branch_id, variant_id)
- KPIs calculados en tiempo real (no materializados)
- `inventory_turnover = COGS / avg_stock` donde COGS = SUM(unit_cost * qty) de ventas del período
