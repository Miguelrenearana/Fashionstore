# CU-34 — Consultar bitácora y trazabilidad del sistema

> Paquete: **Reportes y control administrativo**

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-34 | Permitir al administrador consultar la bitácora de auditoría (AuditLog) con filtros por usuario, acción, entidad, rango de fechas para trazabilidad completa. | Administrador | Administrador |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| Administrador autenticado. Existen registros en AuditLog. | 1. El admin accede a "Bitácora y Trazabilidad". 2. El sistema lista auditoría paginada (usuario, acción, entidad, entidad_id, timestamp, diff). 3. El admin aplica filtros: usuario, acción (CREATE/UPDATE/DELETE/LOGIN), entidad (Product, Sale, User, Inventory, etc.), rango fechas. 4. El sistema muestra resultados filtrados con paginación. 5. El admin puede ver detalle de un registro (diff JSON antes/después). | Trazabilidad completa de acciones críticas del sistema. | Sin permisos → 403. Filtros inválidos → 422. Sin resultados → lista vacía. |

## Endpoints

| Método | Ruta | Descripción |
| --- | --- | --- |
| GET | `/api/v1/reports/audit-log?page=1&size=20&user_id=5&action=UPDATE&entity=Sale&start_date=...&end_date=...` | Bitácora paginada con filtros combinados |

## Validaciones

- Solo rol ADMIN
- `page` ≥ 1, `size` 1-100 (default 20)
- `action` ∈ {CREATE, UPDATE, DELETE, LOGIN, LOGOUT, PAYMENT, REFUND, ADJUSTMENT, RECEIVE, TRANSFER, ...}
- `entity` ∈ {Product, Garment, Variant, Sale, Payment, Receipt, User, Client, Inventory, InventoryMovement, Reception, Promotion, Category, Size, Color, Season, Collection, Supplier, Branch, City, Role, ...}
- `start_date` ≤ `end_date` si ambos presentes
- Filtros combinados con AND lógico

## Modelo de Datos

- **AuditLog**: id, user_id, user_email, action, entity, entity_id, old_values (JSON), new_values (JSON), ip_address, user_agent, created_at
- **AuditLogPageResponse**: items[], total, page, size, pages

## Acciones registradas (ejemplos)

| Entidad | Acciones |
| --- | --- |
| Product/Garment/Variant | CREATE, UPDATE, DELETE (soft) |
| Sale/Payment/Receipt | CREATE, UPDATE, PAYMENT, REFUND, CANCEL |
| User/Client | CREATE, UPDATE, LOGIN, LOGOUT, ROLE_CHANGE |
| Inventory/InventoryMovement | ADJUSTMENT, PURCHASE, SALE, TRANSFER, SHRINKAGE |
| Reception | CREATE, RECEIVE, CANCEL |
| Promotion | CREATE, UPDATE, DELETE |

## Notas

- AuditLog se popula automáticamente vía eventos/domain events o middleware en servicios
- `old_values`/`new_values` almacenan diff JSON para trazabilidad de cambios
- Índices en (user_id, created_at), (entity, entity_id), (action, created_at), (created_at)
- Paginación keyset-friendly para grandes volúmenes
- No hay endpoint de borrado (inmutable)
