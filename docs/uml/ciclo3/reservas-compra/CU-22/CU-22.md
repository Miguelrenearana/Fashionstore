# CU-22 — Consultar historial de compras

> Paquete: **Reservas y experiencia de compra**

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-22 | Permitir al cliente consultar su historial unificado de compras (ventas pagadas) y reservas, con detalles, comprobantes y paginación. | Cliente | Cliente |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| El cliente está autenticado. | 1. El cliente accede a "Mis compras / Historial". 2. El sistema consulta sus ventas pagadas y reservas, combinándolas en una lista unificada ordenada por fecha descendente. 3. El sistema pagina los resultados. 4. El cliente visualiza la lista unificada con: tipo (venta/reserva), referencia, fecha, total, estado, sucursal y cantidad de ítems. 5. El cliente puede hacer click en cualquier item para ver el detalle completo (ítems, comprobante, estado). | El cliente visualiza su historial completo de compras y reservas, con paginación y acceso al detalle de cada transacción. | Cliente no encontrado → 404. Error en base de datos → 500. |

| Método | Ruta | Descripción |
| --- | --- | --- |
| GET | `/api/v1/history` | Historial unificado paginado (ventas + reservas) |

## Campos por tipo

| Campo | Venta (sale) | Reserva (reservation) |
|-------|--------------|----------------------|
| type | "sale" | "reservation" |
| reference | invoice_number | pickup_code |
| date | paid_at / created_at | created_at |
| items | SaleDetail + variant info | ReservationDetail + variant info |
| receipt | receipt_url, receipt_type | N/A |
| expires_at | N/A | expires_at |

## Validaciones

- Cliente debe estar autenticado
- Paginación: page ≥ 1, size 1-100
- Orden: fecha descendente (más reciente primero)
