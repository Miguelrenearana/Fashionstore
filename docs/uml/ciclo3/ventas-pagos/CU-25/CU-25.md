# CU-25 — Procesar pago electrónico

> Paquete: **Ventas, pagos e inventario**

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-25 | Permitir al cliente pagar una venta online mediante gateway QR estático simulado (generación de QR dinámico, página de pago, webhook, polling y auto-completado). | Cliente | Cliente |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| Existe una venta en estado PENDING_PAYMENT. Cliente autenticado (opcional, puede ser invitado). | 1. El cliente inicia el pago desde checkout. 2. El sistema crea un Payment PENDING con referencia única y fecha de expiración del QR. 3. El sistema genera QR SVG y página de pago HTML con el QR. 4. El cliente escanea el QR con su app bancaria o hace click en "Pagar Ahora". 5. El gateway (simulado) recibe confirmación vía webhook HMAC o polling auto-completado. 6. El sistema actualiza Payment a COMPLETED, Sale a PAID, genera comprobante (Receipt). 7. El cliente ve confirmación de pago exitoso. | Payment COMPLETED, Sale PAID, Receipt generado, stock descontado. | Referencia inválida → 404. Firma HMAC inválida → 401. Pago ya completado → 409. QR expirado → TIMEOUT. Monto incorrecto → 400. |

## Endpoints

| Método | Ruta | Descripción |
| --- | --- | --- |
| POST | `/api/v1/payments/initiate` | Iniciar pago (crea Payment + QR) |
| GET | `/api/v1/payments/config` | Configuración del gateway activo |
| GET | `/api/v1/payments/qr/{reference}.svg` | QR code como SVG |
| GET | `/api/v1/payments/qr/{reference}` | Info del pago (monto, merchant, URLs) |
| GET | `/api/v1/payments/pay/{reference}` | Página HTML de pago simulada |
| POST | `/api/v1/payments/webhook/static_qr` | Webhook confirmación pago (HMAC) |
| GET | `/api/v1/payments/qr/status/{reference}` | Polling estado del pago |
| POST | `/api/v1/payments/confirm` | Confirmar pago manual (fallback) |
| POST | `/api/v1/payments/refund` | Reembolso (genera nota de crédito) |

## Validaciones

- `sale_id` debe existir y estar en estado PENDING_PAYMENT
- `amount` debe coincidir con `sale.total_amount`
- Webhook requiere header `X-Signature` HMAC-SHA256 válido
- QR expira a los `static_qr_expires_minutes` (default 15 min)
- Auto-completado a los `static_qr_auto_complete_seconds` (default 30s)
- Idempotencia en webhook (mismo reference + COMPLETED no duplica)

## Modelo de Datos

- **Payment**: id, gateway_reference, sale_id, amount, currency, method, status (PENDING/COMPLETED/DECLINED/REFUNDED/TIMEOUT), qr_expires_at, qr_verified_at, qr_verification_method, qr_webhook_received_at, created_at
- **StaticQRGateway config**: merchant_name, merchant_city, webhook_secret, expires_minutes, auto_complete_seconds

## Notas

- Gateway mock `StaticQRGateway` simula comportamiento de pasarela real (PagosNet, etc.)
- QR contiene solo la referencia de pago (formato QR Simple Bolivia con CRC16 opcional)
- Frontend hace polling cada 5s a `/qr/status/{ref}` hasta COMPLETED/TIMEOUT
- Al completar: `ReceiptService.generate()` crea comprobante automáticamente
