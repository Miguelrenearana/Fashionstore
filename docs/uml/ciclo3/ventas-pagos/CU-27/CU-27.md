# CU-27 — Gestionar existencias por sucursal

> Paquete: **Ventas, pagos e inventario**

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-27 | Permitir a administrador y encargado consultar stock por sucursal/variante y realizar ajustes manuales (corrección, merma, inventario físico) con trazabilidad. | Administrador, Encargado de sucursal (BRANCH_MANAGER) | Admin / Encargado |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| Usuario autenticado con rol ADMIN, MANAGER o BRANCH_MANAGER. Existen sucursales y variantes. | 1. El usuario accede a "Gestión de Existencias". 2. Filtra por sucursal y opcionalmente variante. 3. El sistema muestra tabla: variante, cantidad, reservado, disponible. 4. El usuario ajusta stock indicando cambio de cantidad (+/-) y motivo. 5. El sistema valida que resultado no sea negativo. 6. Actualiza Inventory y crea InventoryMovement (type=ADJUSTMENT). | Stock actualizado en Inventory. Movimiento registrado en InventoryMovement con tipo, cantidad, motivo, usuario, timestamp. | Variante/sucursal no existe → 404. Resultado negativo → 422. Sin permisos sucursal → 403. |

## Endpoints

| Método | Ruta | Descripción |
| --- | --- | --- |
| GET | `/api/v1/inventory?branch_id=1&variant_id=5` | Listar existencias (filtro sucursal obligatorio, variante opcional) |
| GET | `/api/v1/inventory/movements?branch_id=1&variant_id=5` | Historial de movimientos |
| PATCH | `/api/v1/inventory/{branch_id}/{variant_id}/adjust` | Ajustar stock (quantity_change, reason) |

## Validaciones

- `branch_id` obligatorio en listado
- `quantity_change` puede ser positivo (entrada) o negativo (salida)
- `quantity + quantity_change >= 0` (no stock negativo)
- `reason` obligatorio para trazabilidad
- BRANCH_MANAGER solo ve/su sucursal asignada
- ADMIN/MANAGER ven todas las sucursales

## Modelo de Datos

- **Inventory**: id, branch_id, variant_id, quantity, reserved, updated_at (unique branch_id+variant_id)
- **InventoryMovement**: id, branch_id, variant_id, type (PURCHASE/SALE/RESERVATION/ADJUSTMENT/TRANSFER_IN/TRANSFER_OUT/RETURN/SHRINKAGE), qty_change, reason, user_id, created_at

## Notas

- `available = quantity - reserved` (calculado)
- Ajuste genera movimiento type=ADJUSTMENT automáticamente
- Movimientos son inmutables (solo INSERT, no UPDATE/DELETE)
- Índices en (branch_id, variant_id) y (branch_id, created_at)
