# CU-28 — Registrar movimientos de inventario

> Paquete: **Ventas, pagos e inventario**

| CASO DE USO | PROPÓSITO | ACTORES | ACTOR INICIADOR |
| --- | --- | --- | --- |
| CU-28 | Permitir registrar y consultar movimientos de inventario (entradas, salidas, ajustes, transferencias, mermas, devoluciones) con trazabilidad completa. | Administrador, Encargado de sucursal (BRANCH_MANAGER) | Admin / Encargado |

| PRECONDICIÓN | FLUJO DE SUCESO PRINCIPAL | POSTCONDICIÓN | EXCEPCIÓN |
| --- | --- | --- | --- |
| Usuario autenticado con rol ADMIN, MANAGER o BRANCH_MANAGER. | 1. El usuario accede a "Movimientos de Inventario". 2. Filtra por sucursal, variante, tipo, rango de fechas. 3. El sistema lista movimientos (tipo, cantidad, motivo, fecha, usuario). 4. El usuario registra movimiento manual (merma, ajuste, transferencia). 5. El sistema valida tipo y cantidad. 6. Crea InventoryMovement y actualiza Inventory si aplica. | Movimiento registrado en InventoryMovement. Stock actualizado en Inventory (según tipo). | Tipo inválido → 422. Cantidad inválida → 422. Variante/sucursal no existe → 404. Sin permisos → 403. |

## Endpoints

| Método | Ruta | Descripción |
| --- | --- | --- |
| GET | `/api/v1/inventory/movements?branch_id=1&variant_id=5&type=ADJUSTMENT&start_date=...&end_date=...` | Listar movimientos con filtros |
| POST | `/api/v1/inventory/movements` | Registrar movimiento manual {branch_id, variant_id, type, qty_change, reason} |

## Validaciones

- `type` ∈ {PURCHASE, SALE, RESERVATION, ADJUSTMENT, TRANSFER_IN, TRANSFER_OUT, RETURN, SHRINKAGE}
- `qty_change` ≠ 0 (positivo = entrada, negativo = salida)
- `branch_id` + `variant_id` deben existir en Inventory (o crearse si entrada inicial)
- `reason` obligatorio
- BRANCH_MANAGER solo su sucursal
- Movimientos automáticos (venta, compra, reserva) se crean desde sus respectivos servicios, no por este endpoint

## Modelo de Datos

- **InventoryMovement**: id, branch_id, variant_id, type, qty_change, reason, user_id, created_at
- **Inventory**: id, branch_id, variant_id, quantity, reserved, updated_at

## Tipos de Movimiento

| Tipo | Origen | qty_change | Actualiza Inventory |
| --- | --- | --- | --- |
| PURCHASE | Recepción OC (CU-29) | + | Sí (+qty_received) |
| SALE | Venta POS/Online (CU-23/21) | - | Sí (-qty vendida) |
| RESERVATION | Reserva (CU-15) | 0 | Sí (reserved += qty) |
| ADJUSTMENT | Manual (CU-27/28) | +/- | Sí (quantity += qty_change) |
| TRANSFER_IN | Transferencia entrada | + | Sí (+qty) |
| TRANSFER_OUT | Transferencia salida | - | Sí (-qty) |
| RETURN | Devolución cliente | + | Sí (+qty) |
| SHRINKAGE | Merma/pérdida | - | Sí (-qty) |

## Notas

- Movimientos son append-only (auditoría)
- Endpoint POST para movimientos manuales excepcionales (merma, corrección, transferencia)
- La mayoría de movimientos se generan automáticamente desde otros CUs
